
### 비트코인 지갑과 주소의 개념
- #### 비트코인 탄생
	- 신뢰 기관 없이 금처럼 제한된 자산으로 작동하는 암호 화폐
		- 개방형 & 완전 비허가형 네트워크
	- 사토시의 해결책
		- UTXO 기반 트랜잭션
		- 채굴 경쟁을 통한 PoW
		- Longest Chain 선택 규칙
		- 보상 규칙
- #### 지갑(Wallet)
	- 블록체인 네트워크의 암호 화폐를 관리하기 위해 사용하는 도구
		- 개인키/공개키 등을 생성하고 관리 -> 지갑 주소 생성
		- 하나의 지갑에서 여러 개의 주소 생성 가능
		- 잔고 확인 (비트코인 : UTXO 기반 / 이더리움 : 계정 기반)
		- 개인키를 이용하여 전자 서명 생성
- #### 주소(Address)
	- 암호 화폐 송수신에 사용하는 문자열
		- 지갑의 파생 값
		- 노드의 네트워크 IP 주소와 다른 개념
	- 블록체인 네트워크마다 개념 차이 존재
		- (비트코인) : 화폐 잠금, 해제 조건 라벨
		- (이더리움) : 계정 / 컨트랙트의 고정 식별자
- #### 비트코인 주소 생성
	- ECDSA 전자서명 기법의 개인키/공개키를 순차적으로 생성
		- 개인키는 송금 시 본인을 증명하는 전자서명 생성에 사용
		- 공개키는 전자서명 검증에 사용
		- 비가역성 존재
			- Esay : 개인키 -> 공개키 -> 주소
			- Difficult : 개인키 <- 공개키 <- 주소
	- 공개키의 이중 해시값(SHA256 -> RIPEMD-160)에 Base58 인코딩
		- Base58 인코딩 : 사람이 혼동하기 쉬운 숫자(0), 영문(O), 대문자(L), 소문자(l) 등을 제거한 인코딩
### 비트코인 네트워크를 구성하는 노드의 유형 파악 & 비교
- #### 노드가 사용하는 기능 모듈
	- Wallet(지갑)
		- 개인키 / 공개키 관리 및 주소 생성
		- 트랜잭션 발송, 송금, 서명 승인, 잔액 조회 등
	- Full Blockchain(블록 저장 및 검증)
		- 블록체인 전체 데이터 저장
		- 블록 동기화, 트랜잭션 유효성 검증
	- Network Routing Node(네트워크 라우팅)
		- P2P 네트워크 통신 및 데이터 전파
		- 블록 전달, 피어 연결
	- Miner(채굴)
		- 작업 증명으로 블록을 만들고 전파
		- 채굴 퍼즐 풀이
- #### 비트코인 노드 종류
	- Reference Client (Bitcoin Core)
		- 모든 기능을 다 활용하는 노드
		- 초창기 표준 노드
	- Full Blockchain 노드
		- "풀 노드"라고 불리우며 블록체인 데이터 전체를 관리하는 노드
		- 2009년 1월 3일부터 현재까지의 모든 트랜잭션들이 보관되어 있음
		- 풀 노드가 최근 트랜잭션이 담긴 새로운 블록을 받으면 합의 알고리즘 수행
			- 유효성 검증 -> 블록체인에 연결 -> 다른 노드들에게 전파
	- Lightweight wallet 노드
		- SPV노드라고 불리며 블록체인 전체가 아닌 블록의 헤더 정보만 가지고 있음
		- 새로운 블록이 생성되면 풀 노드로부터 블록 헤더를 받아 자신의 헤더 체인에 연결
		- 주로 스마트 기기 등 소형 장비에 적합함
		- 트랜잭션이 블록체인에 포함되었는지 확인하기 위해 관련 정보를 풀 노드에게 요청
	- Solo Miner
		- 블록체인 네트워크를 유지하는데 필수적인 구성원
		- 채굴자들은 경쟁적으로 수학적 퍼즐을 풀고 블록 헤더에 그 해답을 제시함
		- 먼저 해답을 제시한 채굴자의 블록이 Full Blockchain Node로 전송되며, 이 해답에 대한 유효성 검증이 끝나면, 그대가로 보상을 받음
- #### 노드의 네트워크 연결
	- Peer 발견
		- 캐시 활용 Peer 검색 : 이전에 연결했던 노드의 IP 주소를 내부 캐시에서 불러와 먼저 연결 시도
		- DNS Seed 노드 통한 검색 : 연결 실패 시 커뮤니티에서 관리하는 DNS Seed 서버에서 접속 가능한 IP 주소 조회
		- 하드코딩된 Seed IP 주소 사용 : 실패시 클라이언트에 하드코딩 된 Seed 노드의 IP 주소 목록을 이용
	- 연결 요청 및 핸드 셰이크
	- 주소 전파 및 확장
		- 자신의 IP 주소를 이웃에게 전파, 상대의 이웃 목록을 받아 연결 확장
	- 블록체인 동기화
		- 연결한 노드로부터 최신 데이터 다운로드
	- 네트워크 유지 및 경로 복구
		- 주기적으로 이웃의 활성 상태를 확인, 연결이 끊기면 새로운 경로 수립하여 연결 유지
- #### 비트코인 네트워크
	- 그 외 채굴 집단, 채굴 중앙 서버 등 특수 목적 노드 존재
### 비트코인 블록의 구조, 포함되는 정보의 의미
- #### 제네시스 블록
	- [[5.비트코인_2026.pdf#14]]
- #### 비트코인 블록 시퀀스
	- 여러 개의 블록이 사슬처럼 연결된 구조
	- 각 블록은 블록 헤더와 블록 바디로 나눌 수 있음
		- ##### Header : 블록을 고유하게 식별하고 연결을 보장하는 정보를 담은 메타데이터
			- 버전
				- 블록을 생성할 때 사용된 SW/프로토콜 버전
				- 소프트포크와 같이 기능 변화 시 변경
			- 이전 블록해시
				- 바로 직적 블록 헤더의 내용을 이중으로 해시
			- 머클루트
				- 포함된 트랜잭션 전체를 머클 트리로 합산한 최종 해시
				- SHA-256 해시 사용
				- 코인베이스 트랜잭션도 포함
				- 트랜잭션이 하나이거나 홀수개로 존재하는 경우
					- 1개 : 해당 트랜잭션의 해시 값이 그래도 머클루트로 사용
					- 홀수개 : 마지막 트랜잭션을 복사해서 짝수개로 균형 맞춤
			- 타임스탬프
				- 블록이 생성된 시점
				- 유닉스 시간
				- 비정상적인 블록 생성을 방지하기 위한 존재 값
				- 이전 11개 블록의 타임스탬프와 중간값보다 커야 함
				- 네트워크 시간보다 2시간 이상 미래이면 안됨
			- 난이도(Bits)
				- 작업증명에서 풀어야 하는 해시 퍼즐의 난이도
				- 주어진 공식으로 Bits 값으로 목표 값 계산
				- 블록 해시가 제시하는 목표 값 이하가 되어야 유효
				- 채굴 속도에 따라 공식에 의해 자동으로 조절
			- 넌스
				- 블록 해시를 계산할 떄 사용한 일회용 난수 값
		- ##### Body : 블록에 포함된 트랜잭션 리스트
			- 트랜잭션 카운터
				- 해당 블록에 포함된 트랜잭션의 개수
			- 코인베이스 트랜잭션
				- 블록의 첫 번째 트랜잭션
				- 채굴자에게 주어지는 보상이 기록
				- 신규 발행 비트코인
				- 해당 블록에 포함된 모든 트랜잭션 수수료
			- 트랜잭션 리스트
				- 각 트랜잭션은 입력, 출력, 서명 등으로 구성
				- 서명을 블록 외부에 두는 경량 구조도 지원 (Segwit)
		- 블록 예시
			- [[5.비트코인_2026.pdf#19]]
### UTXO 모델의 개념 이해 & 특징 파악
- #### UTXO 모델
	- [[5.비트코인_2026.pdf#20]]
	- 아직 쓰이지 않는 트랜잭션의 출력이라는 의미
	- 거래기반 방식
		- 지갑의 잔액이 숫자로 기록되는 것이 아니라 사용할 수 있는 UTXO의 합으로 표기
	- 특징
		- 받은 금액 그대로가 UTXO로 생성되어 저장
		- 일부 금액을 송금할 경우 새로운 UTXO를 생성하고 기존 UTXO는 파기
### UTXO 기반 트랜잭션 구조와 작동 원리
- #### UTXO 모델에서의 트랜잭션
	- 개별 거래를 입금과 출금으로 구성하여 구조화
	- ##### 트랜잭션 구조
		- 입력(Input)
			- 송금자는 자신이 소비하는 UTXO에 대한 소유권을 증명
			- UTXO는 스크립트에 의해 잠겨 있으며 해제 조건이 충족될 경우에만 사용 가능
			- 잠김을 해제할 수 있음을 보임으로써 소유권을 증명하게 됨
		- P2PKH(Pay to Public Key Hash) 방식의 소유권 증명 시
			- 공개키의 해시 값을 사용하여 UTXO가 잠겨 있음
			- 해당 공개키에 대응하는 개인키를 가진 사람만이 서명을 생성하여 잠금을 해제
		- 출력(Output)
			- 수신자 지갑의 공개키로 송신하는 금액
			- 지갑 주소와 검증 조건이 담긴 잠김 스크립트
			- P2PKH : 공개키 해시 사용, 표준 방식
			- P2SH(Pay to Script Hash) : 복합 조건, 다중 서명 방식
			- \[Segwit 적용] P2WPKH, P2WSH 등 다양한 잠금 방식 존재
	- ##### 트랜잭션 수수료
		- 트랜잭션의 모든 입력 금액의 합에서 모든 출력 금액의 합을 뺀 차액
		- 지갑에서 권장 수수료를 자동으로 계산
			- 데이터의 크기, 네트워크 상황 등을 분석
			- 사용자가 직접 선택 및 조정 가능
		- 채굴자는 수수료가 높은 트랜잭션을 우선적으로 블록에 담음
			- 빠르게 거래를 성사시키고 싶으면 높은 수수료를 지불하는 것이 유리
- #### 코인베이스 트랜잭션
	- 채굴자에게 주어지는 보상이 기록된 트랜잭션
		- 새롭게 발행되는 금액이 주어지는 개념
		- 이전 트랜잭션의 UTXO의 금액이 보내지는 것이 아님
	- 입력 필드의 특징
		- 이전 트랜잭션을 참조하지 않음
		- ScriptSig에 임의 데이터 작성 가능
	- 출력 필드의 특징
		- 블록 보조금 + 해당 블록 내 모든 트랜잭션 수수료의 합
- #### Segwit (Segregated Witness)
	- 2017년 소프트포크로 활성화
	- 트랜잭션의 **서명 데이터를 본문에서 분리**하여 처리속도 및 확장성을 높임

### 비트코인 채굴과 합의 알고리즘
- #### 비트코인 채굴 및 합의 알고리즘
	- 해시 기반 퍼즐
		- 계산한 해시값 h가 타겟 값 T보다 작을 때까지 넌스를 변경하며 반복시행
		- 정해진 비트 난이도(nBits)로 T값 계산
			- 채굴자는 풀노드에게 nBits를 요청
			- 풀노드는 2016번째 생성 블록마다 nBits 값을 새롭게 계산
			- 평균 10분마다 한 블록이 생성될 수 있도록 조절
- #### 타겟 값 복원
	- nBits : 0xee7ccccc
		- E : 0xee (nBits의 상위 1바이트)
		- C : 0x7ccccc (nBits의 하위 3바이트)
	- 32바이트 빅엔디안으로 표기 시
		- [[5.비트코인_2026.pdf#35]]
- #### 블록 보조금 반감기 (Halving)
	- 대표 블록 선정으로 받는 블록 보조금이 210,000블록마다 절반으로 감소
	- 비트코인 총 공급량은 약 2,100만개로 한도가 정해져 있음
- #### 비트코인 네트워크 동작 정리
	- 분산 장부 합의 상태에서 트랜잭션이 새롭게 생성되고 전파됨
	- 수신 노드는 자신의 지갑을 통해 받은 트랜잭션을 검증
		- 검증 항목
			- 디지털 서명
			- UTXO
			- 스크립트
		- 검증이 완료되면 노드의 메모리풀에 저장함
			- 노드 간 자신의 메모리풀 정보를 일부 교환하거나 공유하기도 함
	- 채굴을 위해 메모리풀 내 트랜잭션을 모아서 후보 블록 생성
		- 수수료 등을 고려하여 자율적으로 트랜잭션 선택
		- 난이도를 고려한 해시 퍼즐의 정답을 찾음
	- 작업 증명을 마친 채굴자는 자신이 찾은 후보 블록을 네트워크에 전파
		- 자신의 블록 시퀀스에 작업 증명으로 찾은 후보 블록을 연결
	- 블록을 받은 노드는 검증 과정을 거치고 자신의 블록 시퀀스에 연결
		- 블록 검증 항목
			- 이전 블록 해시
			- 트랜잭션
			- 머클 루트
			- 작업 증명 결과
	- 동시에 두 개 이상의 후보 블록이 발생할 경우 가잔 긴 체인 규칙으로 대표 선정
		- 긴 체인으로 연결된 블록들이 한번에 대표로 선정하고 이후 공식 블록 시퀀스에 연결
		- 대표 블록을 생성한 채굴자에게 보상 수여
		- 대표 블록 내 트랜잭션은 메모리풀에서 삭제
