
## 1. 블록체인을 위한 암호기술
### 해시 함수의 역할과 성질
- #### 해시 함수
	- 데이터가 위변조되지 않았음을 보장하는 대표 암호 기술
		- 임의의 크기의 데이터를 입력 -> 고정된 크기의 데이터를 출력
- #### 암호학적 해시 함수의 보안 성질
	- 역상 저항성
		- 함수 정보 h()와 해시 값 y가 주어졌을 때
		- h(x) = y를 만족하는 x를 찾는 것이 어려움
	- 제 2역상 저항성
		- 함수 정보 h() 메시지 x가 주어졌을 때
		- h(x) = h(x') 이고 x != x' 를 만족하는 x'를 찾는 것이 어려움
	- 충돌 저항성
		- 함수 정보 h()가 주어졌을 때
		- h(x) = h(x')이고 x != x'를 만족하는 (x, x') 쌍을 찾는 것이 어려움
- #### 해시 함수의 역할
	- 데이터의 지문
		- 특정 데이터에 대응하는 사실상 고유한 표식 역할
		- 눈사태 효과 : 입력의 한 비트 차이가 출력의 완전한 변화를 일으킴
- #### 해시 함수의 종류
	- MD 계열
		- 과거 널리 사용, 보안 취약점 발견되어 현재 권장 X
		- MD2, MD4, MD5
	- SHA-1
		- 160비트 해시 값을 생성
		- SSL 프로토콜에 사용되었으나 현재 충돌쌍을 찾는 공격 가능
	- SHA-2
		- 224, 256, 384, 512 비트 해시 값을 생성
		- 현재까지 사용 but, 잠재적인 취약점 존재
	- SHA-3
		- Keccak 알고리즘이 최종 선정
	- MD 구조의 취약점을 제거하고자 스펀지 구조로 새롭게 설계
	- BLAKE 계열
		- ChaCha 경량 암호화 알고리즘 사용 + 병렬 최적화 가능 -> 높은 성능
		- RFC 7693 표준화
	- Poseidon
		- 대수적 회로에서 효율적으로 동작하도록 설계
		- 증명 친화적 알고리즘 : "주어진 해시 값에 대한 입력을 알고 있다"는 주장에 대한 영지식 증명을 효율적으로 할 수 있음
### 머클 트리와 이를 기반한 증명방식
- #### 머클 트리
	- 다수의 데이터를 해시로 요약해 루트 해시(=머클 루트)로 묶는 트리 구조
		- 방대한 데이터에 대한 무결성을 효율적으로 검증
		- 모든 자식 노드의 데이터에 대해 단계적으로 해시 함수를 계산
		- 최상단의 루트 해시만 검증해도 모든 데이터의 수정 여부를 체크하게 됨![[스크린샷 2026-10-13 at 21.35.25 2.png]]
- #### 머클 트리 기반 증명
	- 데이터가 트리에 포함되어 있음을 효율적으로 증명
		- 전체 데이터를 알고 있을 필요 없이 루트 해시 값과 머클 경로만 알면 됨
		- 머클 경로의 크기는 N개의 데이터에 대해 0![[스크린샷 2026-10-13 at 21.36.52.png]]
### 전자서명의 개념과 역할
- #### 전자서명
	- 전자적인 문서를 전달할 때 메시지의 무결성과 송신자 인증을 제공
		- 디지털 인감 도장
		- 공인된 인증 기관으로부터 서명을 검증할 수 있는 인증서 발행
- #### 전자서명 과정
	- 공개키 암호의 역 변환 개념
		- RSA 알고리즘에 의해 실제로 사용되기 시작
		- (암호) 공개키에 의한 암호화 - 개인키에 의한 복호화
		- (서명) 개인키에 의한 서명 - 공개키에 의한 검증
	- 메시지 길이가 긴 경우
		- 해시 함수를 이용하여 메시지 대신 이에 대한 해시 값으로 전자서명을 생성함
- #### 전자서명 제공 성질
	- 무결성
		- 내용을 변경하려면 서명키를 알아야 함
	- 메시지 출원 인증
		- 누가 서명했는지 신원 확인 가능
	- 부인 방지
		- 서명자는 자신이 서명한 사실을 부인할 수 없음
- #### 전자서명 대표 기법
	- RSA
		- 큰 두개의 소수 곱을 나머지 연산의 기준 값으로 사용 (소인수분해 시 안전성 파괴)
		- PKI 환경 인증서 기반 기술로 다양한 분야 활용
		- but, 서명의 크기가 크고 생성, 검증 속도가 느려 블록체인에 적합하지 않음
	- ECDSA
		- 타원 곡선 기반 서명
		- RSA보다 상대적으로 짧은 키로 강력한 보안 수준 제공
			- RSA 3072비트 ~ 128비트 보안강도 ~ 타원곡선 256비트
		- 널리 검증되고 표준화된 알고리즘
		- 비트코인, 이더리움에 사용
	- EdDSA
		- 주로 Ed25519 커브 사용 (일반 커브보다 연산이 단순하고 빠름)
		- 난수 생성 대신 메시지 기반 해시 값 사용, 연산 과정이 일정하여 부채널 공격에 강함
		- 솔라나, 카르다노, 모네로 등에 사용
		- RSA, ECDSA에 의존하는 기존 시스템과의 호환성 문제
		- 2017년 표준에 제정되어 안전성 검증 기간이 상대적으로 짧음
### 고급 전자서명의 특징
- #### 집계 서명
	- 여러 명이 각자 생성한 서명을 하나의 단일 서명으로 합치는 기술
	- 검증자는 하나로 집계된 개별 서명을 한 번에 확인 가능
	- 특징
		- 높은 검증 효율성 : 개별 검증을 할 필요 없이 한 번만 필요
		- but, 단일 서명 기준으로 ECDSA, RSA보다 계산 비용이 큼
	- 이더리움 2.0의 대규모 합의 시스템에 사용
		- 사용 기법 : BLS 서명
- #### 다중 서명
	- 동일한 메시지에 대한 서명 권한을 여러 참여자에게 공동으로 나누는 기술
	- 여러 개의 독립적인 개인 키가 모이면 최종적으로 유효한 서명 값 생성
		- t-of-N 방식 : N명 중 t명 이상 모이면 성립
		- 검증자는 최소 t명 참여자들이 동일한 메시지에 서명한 것으로 간주
	- 일부 키가 유출되거나 분실 되어도 안전함
	- 블록체인 지갑, DAO 의사 결정 등에 활용
### 영지식 증명의 개념
- #### 영지식 증명 (Zero-Knowledge Proof, ZKP)
	- 어떤 문장의 비밀 내용을 공개하지 않고 내용이 사실임을 증명하는 방법
	- 검증자는 내용 자체는 모르지만 "문장의 진실성"만 확인
	- (내용을 알고있다는 사실을 검증)
- #### 영지식 증명의 제공 성질
	- 완전성
		- 문장이 참이면 검증자는 항상 True 출력
	- 건전성
		- 문장이 거짓이면 검증자가 True를 출력하게 만들 수 없음
	- 영지식성
		- 문장이 참이라는 사실 외 어떠한 정보도 노출하지 않음
- #### 영지식 증명 대표 기법
	- Fiat-Shamir 기반 ZKP, zk-SNARKs, zk-STARKs 등
- #### 영지식 증명 활용
	- 프라이버시 보호
		- DID : 실제 생년원일을 공개하지 않고 성인임을 증명, 여권 번호를 공개하지 않고 특정 국가의 시민임을 증명
	- 블록체인 확장성 제공
		- 무거운 트랜잭션 검증 과정을 체인 밖에서 처리하고 결과만 블록체인에 기록
		- Layer 2 롤업 : 수천 개의 트랜잭션 내 민감한 정보를 숨기면서 유효성을 간결하게 증명 

## 2. 합의 알고리즘
### 블록체인 네트워크에서 합의가 필요한 이유
- #### 블록 생성 및 기록 (Review)
	- 블록 생성에 참여하는 노드는 블록 구조에 필요한 값들을 결정해서 채워 감
	- 분산 구조에서는 각 노드가 이미 생성한 서로 다른 후보블록이 존재
	- 합의규칙에 따라 각 노드는 네트워크 자신이 따를 대표 블록을 선정
	- 일시적으로 선택 블록이 다르더라도 전체 노드의 장부가 대표 블록을 기록한 장부로 동기화
- #### 합의 알고리즘
	- 분산 네트워크에서 모든 정직한 노드가 같은 상태에 도달하도록 만드는 규칙
	- 블록체인에서의 합의
		- 정직한 노드가 동일한 장부를 가질 수 있도록 블록이 연결되게 하는 것
		- 비정상적이거나 악의적인 노드가 있더라도 동일한 블록 시퀀스에 최종적으로 확정
	- 핵심 요소
		- 안전성, 생존성, 최종성, 장애 허용
- #### 합의 알고리즘의 필요성
	- 네트워크 환경에 의해 발생하는 위협
		- 패킷 지연, 손설 : 같은 시각에 서로 다른 블록으 생성 또는 받게 됨
	- 비잔틴 장군으로부터 발생하는 위협
		- 이중 지불 : 서로 다른 상대에게 동일한 자산을 보내는 트랜잭션을 네트워크에 전파
		- 검열 & 블로킹 : 특정 트랜잭션을 의도적으로 제외
		- 스팸 : 불필요한 메시지를 대량 전송해 네트워크 자원을 소모하고 서비스 장애를 일으킴
		- Sybil 공격 : 자원을 통제하고 가짜 노드를 무제한 생성해 다수인 척 영향력 행사
### 체인 분기와 분기 선택 규칙
- #### 체인 분기
	- 서로 다른 대표 블록이 동시에 2개 이상 생성되어 장부가 일치하지 않게 됨
		- 네트워크 지연, 블록 동시 제안, 악의적 공격, 경제적 동기 등의 원인
	- 블록체인 네트워크에서 합의 중 자연스럽게 발생하는 상황
		- 자연 분기, 우발적 분기라고도 함
- #### 분기 선택 규칙
	- 생존성을 위해 빠르게 수렴하도록 동일한 기준으로 신뢰 가지를 선택
		- Longest Chain Rule(BTC), GHOST(ETR), 2/3이상 투표(BFT계열)
	- 최장 체인 규칙 (Longest Chain Rule)
		- 가장 길게 연결된 체인을 선택하여 계속 연결 (PoW 방식)
		- 시간이 지날수록 한 가지로 수렴 -> 확률적 최종성 제공
	- ##### 분기 선택 시나리오 예시
		- [[4.합의 알고리즘_2026.pdf#page=10]]
- #### 다른 유형의 분기
	- 네트워크를 운영하는 규칙이 바뀜으로써 발생
		- 규칙이 분기된다는 맥락으로 체인이 갈라지는 것과 다른 개념
	- 하드포크
		- 규칙이 변경되어 옛 노드와 호환 불가
		- 업그레이드 불일치가 계속되면 두 종류의 체인으로 분리되어 공존
	- 소프트 포크
		- 규칙이 엄격하게 바뀌어 옛 노드도 새 규칙을 부분적으로 수용
		- 하나의 체인으로 유지
### 대표 합의 알고리즘의 종류별 특징
- #### 작업 증명 (Proof of Work, PoW)
	- 대표 후보 블록을 생성하기 위해 어려운 퍼즐을 푸는 과정을 포함하는 구조
		- 퍼즐의 답을 찾기 위해 많은 연산을 하고, 작업의 결과를 블록에 담아 증명하는 개념
		- 보상을 받기 위한 답은 찾기 어렵지만 검증은 쉽게 하는 것이 퍼즐의 원칙
		- 정직하게 블록을 만들면 보상이 주어지지만 부정행위는 비용이 들고 쉽게 발견됨
- #### 작업 증명 과정
	- 채굴자의 동작 과정
		1. 트랜잭션 묶음 후보 구성
		2. 퍼즐 입력 및 난이도 확인
		3. 퍼즐 풀기
		4. 성공 시 블록에 증명을 담아 전파
		5. 대표 블록 선정 시 보상을 받음
	- 단순 작업 구조, 저비용 검증
	- But 느린 처리 속도, 과다한 자원 소비, 51% 공격
- #### PoW 대표 퍼즐
	- 해시 퍼즐
		- 주어진 데이터와 넌스를 결합해 특정 조건을 만족하는 해시 값을 찾는 문제
		- 넌스 : 한 번만 사용되고 매번 달라지는 값
		- 답은 미리 알 수 없고 반복적인 시도를 통해서만 찾을 수 있음
		- 특정 하드웨어가 과도하게 유리하지 않도록 퍼즐을 디자인하는 것도 중요
			- 비트 코인은 전용장비 ASIC 등장
- #### 지분 증명 (Proof of Stake, PoS)
	- 합의 투표에 참여할 권한을 자산 지분에 따라 선정하는 구조
		- 각 노드는 자신의 지분이 높을 수록 합의 투표에 참여할 권한을 얻을 확률이 높아짐
		- 규칙 위반 시 예치한 자산이 몰수되므로 경제적 담보로 정직성을 이끌어냄
- #### 지분 증명 과정
	- 검증자의 동작 과정
		1. 자산을 예치하여 검증자로 등록
		2. 네트워크 규칙에 의해 무작위로 검증 위원 배정
		3. 블록이 제안되면 검증 위원은 이를 검증하고 투표
		4. 블록 승인 시 검증 위원에게 보상 지금
			1. 검증 과정에서 부정 행위 시 지분 삭감
	- 적은 에너지 소모, 속도 향상
	- But, 부의 집중에 따른 중앙집권화 위험, 공정한 선출 알고리즘 설계의 복잡성
- #### 위임 지분 증명 (Delegated Proof of Stake, DPoS)
	- 지분을 가진 노드가 대표 집단을 투표로 선출
		- 일반 노드가 대리투표 방식으로 의사결정에 참여하는 민주적인 방식
		- 대표자는 규칙을 어기면 표로 심판 받아 교체될 수 있으므로 정직하게 행동하게 됨
- #### 위임 지분 증명 과정
	- 대표자의 동작 과정
		1. 절차에 따라 검증 받은 노드가 후보로 등록
		2. 지분을 가진 일반 노드가 후보에게 투표
		3. 상위 득표 후보 여럿이 블록 생성자로 선정
		4. 나머지 대표가 제안 블록을 검증하고 서명
		5. 블록 승인 시 대표자와 이에게 투표한 노드에게 모두 보상 분배
	- 매우 높은 확장성, 효율적인 거버넌스
		- 거버넌스 : 한 조직이나 공동체가 어떻게 결정하고, 그 결정을 어떻게 집행하고, 잘 했는지 어떻게 감독하는지를 정하는 의사결정 체계
	- But, 대표자 소수에 권력이 집중
- #### PBFT (Practicla Byzantine Fault Tolerance)
	- 비잔틴 장군 문제를 효율적으로 해경하는 알고리즘
		- 모든 노드의 투표로 2/3이상 동의 시 블록이 즉시 결정적으로 확정되는 방식
		- 참여자 수가 많아지면 메시지가 폭증하여 성능 저하 -> 허가형 블록체인에 적합
	- 비잔틴 문제
		- 분산 네트워크 환경에서 악의적인 노드가 존재할 경우 어떻게 이를 극복하고 합의에 도달할 것인지에 대한 문제
