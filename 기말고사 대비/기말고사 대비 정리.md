## Part 1. 핵심 내용

### 9주차 — Solidity (1)
- **Solidity**: 이더리움 스마트 컨트랙트용 도메인 특화 언어, C 계열 문법, **정적 타입**, 상속·인터페이스·라이브러리 지원
  - 솔리디티 모노컬처: 상호운용성·조합성·개발 비용↓ vs 공통 취약점 내재
- **컨트랙트 구조**: 라이선스 식별자 → 지시문(`pragma`, `import`) → 컨트랙트 코드(생성자, 변수, 함수, 이벤트, 에러, 모디파이어)
  - 라이선스: MIT(상업적 사용까지 허용) / Apache-2.0(MIT + 특허 조항) / GPL-3.0(결과물도 GPL, 코드 공개 필수) / Unlicense(저작권 최대한 포기). 미표기 시 경고(0.6 이상)
  - `pragma ^0.8.3` = 0.8.3 이상 0.9.0 미만
  - **생성자**: 배포 시 **한 번만** 실행되는 초기화 함수
- **EVM 데이터 위치**

| 위치 | 특징 |
|---|---|
| storage | 상태변수가 **영구** 저장, 읽기·쓰기 모두 가스 큼 (CA의 storageRoot로 식별) |
| memory | 함수 실행 중에만 존재(휘발성) |
| calldata | 외부 호출 입력값, **읽기 전용** 임시 공간 |
| stack | 계산용, **1024단계** 초과 시 예외 |

- **변수 종류**: 전역(`block.timestamp`, `msg.sender`, `msg.value`, `tx.origin` 등, 읽기 전용) / 상태(영구, 함수 밖 선언) / 지역(스택·메모리, 상태변수보다 훨씬 저렴)
- **값 타입 vs 참조 타입**
  - 값 타입(bool, uint, address, enum…): 복사 시 **독립된 사본**
  - 참조 타입(string, array, struct, mapping): 위치(storage/memory/calldata) **명시 필요**, 같은 공간을 가리킬 수 있음

| 소스 → 타겟 | 결과 |
|---|---|
| memory → memory | **참조** |
| storage → storage | **참조** |
| memory ↔ storage | 복사 |
| calldata → memory / storage | 복사 |

- **정수**: `uint8`: 0~2⁸−1, `int8`: −2⁷~2⁷−1, `uint`=`uint256`. 연산자 `+ - * / % **`, 비트 `& | ^ ~`, 시프트 `<< >>`
- **address**: 20바이트. `address` vs `address payable` (**transfer / send / call(송금)은 payable만**)
  - `balance`(wei) / `transfer`(실패 시 revert) / `send`(실패 시 false) / `call`(범용 호출) / `delegatecall`(**남의 코드만 빌리고 저장소는 내 것**)
  - transfer·send는 0.8.31부터 deprecated
- **bytes1~bytes32**(고정, 값 타입) / 동적 `bytes`는 참조 타입
- **enum**: 유한 상수 집합, 초기값은 0번째 / **함수 타입**: internal·external 두 종류

### 10주차 — Solidity (2)
- **배열**: 고정 `T[k]`, 동적 `T[]`. `uint[][3]` = 동적 배열 3개짜리 배열, `bool[2][]` = 크기 2 배열의 동적 배열
  - `push()`는 동적 배열만. **string은 index 접근 불가**(EVM에선 둘 다 바이트 배열)
- **struct**: 변수 그룹화 사용자 정의 타입
- **mapping(keytype => valuetype)**
  - 크기 제한 없음, **storage에만 선언**
  - keytype: 기본형 가능 / **다른 mapping·struct·동적 배열 불가**. valuetype: 무엇이든 가능
  - **매핑 전체 delete 불가, 키 단위 delete 가능**
- **타입 캐스팅**: 작은 → 큰 타입은 안전(자동), 큰 → 작은 타입은 **데이터 손실** 가능 (`int8 y = -3; uint8(y)`)
- **단위**: 1 gwei = 10⁹ wei, 1 ether = 10¹⁸ wei / 1 minutes = 60 seconds … 1 weeks = 7 days, 1 year = 365 days
- **전역 변수·함수**: `block.basefee/chainid/coinbase/gaslimit/number/timestamp`, `blockhash(n)`(최근 **256개** 블록만), `gasleft()`, `msg.sender/value`, `tx.gasprice`, `tx.origin`
  - 수학·암호: `addmod`, `mulmod`(오버플로 없이), `keccak256`, `sha256`, `ripemd160`, **`ecrecover`(서명에서 서명자 주소 복구, 실패 시 address(0))**, `abi.encode`
- **가시성**: public(누구나) / private(해당 컨트랙트만) / internal(해당 + **상속받은** 컨트랙트) / external(**외부에서만**, 내부 호출 불가)
- **속성**: `view` = 상태 **읽기만**, `pure` = 상태 **읽지도 쓰지도 않음**
- **제어 구조**: if/else/while/do/for/break/continue/return 있음, **switch·goto 없음**
- **에러 처리**

| | 용도 / 동작 |
|---|---|
| `require(cond, msg)` | 입력·외부 요소 검증, 실패 시 **상태 되돌림** |
| `revert(msg)` | 실행 중단 + 상태 되돌림 |
| `assert(cond)` | **내부 상태 불변식** 검사. 강의 기준: 실패 시 **모든 가스 소비** |

- **modifier**: 함수 실행 전후 동작 자동 추가. `_;` 가 **함수 본문이 실행되는 위치**. 접근제어·사전조건·재진입 방지에 사용
- **event**: 트랜잭션 **로그(receipt)** 에 저장, 블록체인에 데이터를 **가장 저렴하게** 기록. `emit`으로 발생
- **상속**: `is`, **다중 상속 가능**, 부모에 `virtual`, 자식에 `override`. 제한을 강화하는 방향으로 변경 가능 (view → pure)

### 11주차 — 토큰 시스템 구현
- **코인 vs 토큰**

| | 코인 | 토큰 |
|---|---|---|
| 블록체인 | **자체** 블록체인 | **기존** 블록체인 위에서 발행 |
| 발행 | 프로토콜에 따라 자동 | 스마트 컨트랙트 코드로 규칙 정의 |
| 사용처 | 생태계 전체 | 특정 서비스 내부 |
| 예 | BTC, ETH, SOL | ERC-20 기반 USDT, USDC |

- **기본 토큰 구성**: 상태변수 `name, symbol, decimals, totalSupply` + `mapping(address => uint) balanceOf` + 생성자(초기 발행) + `transfer()` + `event Transfer`
  - 총발행량 = `supply * 10 ** decimals` (컨트랙트 내부는 **최소 단위**로 동작), 배포자가 전량 보유
- **transfer() 흐름**: ① 잔액 검사 `balanceOf[msg.sender] >= amount` ② 오버플로 검사 `balanceOf[to] + amount >= balanceOf[to]` (0.8.x부터는 자동 체크) ③ 차감·가산 ④ `emit Transfer`
  - 이벤트의 이유: 프론트/백엔드가 변화 감지, 검색 가능한 이력, **ERC-20 표준 명세**
- **블랙리스트**: `address owner`, `mapping(address => bool) blackList`, `onlyOwner` 제한자, 등록/삭제 함수 + 이벤트. `transfer`에서 **보내는 주소·받는 주소 둘 다** 검사
  - 예제 시나리오: 블랙리스트 등록된 B는 송금도 수신도 불가, B가 A를 블랙리스트에 올리려 해도 `onlyOwner` 때문에 실패
- **캐시백**: `mapping(address => uint) cashbackRate`. 각 주소가 **자기 비율만** 설정(0~100, 100 초과 시 100으로 보정). 소유자도 타인 비율 변경 불가. 송금 시 캐시백 금액을 제외하고 송금
- **회원 관리**: 구조체 `GradeStatus(grade, times, sum, rate)`, `MemberHistory(times, sum, statusIndex)`. 거래 횟수·금액이 기준 충족 시 등급 상승 → 캐시백 비율 변경
  - 토큰 컨트랙트 ↔ 회원 관리 컨트랙트가 서로 주소를 지정(`setToken`, `setMembers`), 회원 관리 쪽은 `onlyToken`(msg.sender == hlToken)으로 보호
  - 소유자 관리 기능은 별도 컨트랙트로 작성해 **상속**

### 12~13주차 — 가스 최적화 · 스마트 컨트랙트 보안
**가스 기본**: 수수료 = 가스 사용량 × (기본 요금 + 우선 요금). 한도 ≥ 트랜잭션 비용 = 실행 비용 + **기본 21,000** + calldata 비용 + 기타

**설계 단위 최적화**
- **온체인·오프체인 분리**: 해시(요약)만 온체인, 상세는 오프체인 DB (예: 투표 내역)
- **작업 단순화**: 다수 사용자 루프 대신 "누가 얼마 받을 수 있는지 기록 → 각자 **claim**"
- **모듈화**: 기능별 분리, 자주 호출되는 함수에 최적화 집중 (단, 컨트랙트 간 호출로 수수료 증가)

**코드 단위 최적화**
1. **스토리지 최소화**: 값을 메모리/지역 변수에 캐싱, 계산은 메모리에서 하고 **최종 결과만** 스토리지에 기록
2. **calldata 사용**: 읽기 전용 외부 함수 인자는 `memory` 대신 `calldata` (복사 생략, 약 **35%** 절감)
3. **constant / immutable**: constant = **컴파일 시점** 확정, immutable = **배포 시 한 번** 설정. 둘 다 스토리지 읽기 불필요
4. **unchecked { }**: 0.8.x의 자동 오버/언더플로 체크는 가스 소모 → 범위가 확실히 안전할 때만 해제 (`require`로 논리 검증 필수)
5. **modifier 리팩터링**: modifier 코드는 적용 함수마다 **복사(inline)** 되어 배포 가스↑ → 공통 로직을 **내부 함수**로 빼고 modifier에서 호출
6. **조건 검사 순서(단락 평가)**: `A && B`는 A가 false면 B 생략, `A || B`는 A가 true면 B 생략 → **가벼운 조건을 앞**, 무거운 조건(외부 호출, 루프, 스토리지 접근)을 뒤로

**보안 필요성**: 배포 후 수정·롤백 어려움(버그 픽스도 불가), 취약점 = 직접 자산 피해, 코드가 공개되어 누구나 검토 가능 (Etherscan verified contracts)

**재진입(Reentrancy)**
- 외부 호출 후 **상태 업데이트 전에** 공격 컨트랙트가 `withdraw()`를 다시 호출 → 잔액 갱신 전 반복 인출
- 메커니즘: `call()` → 공격자의 `fallback()/receive()` 자동 실행 → 다시 `withdraw()`
- 사례: **2016 DAO 해킹**, 약 **360만 ETH**(당시 약 7천만 달러) 유출
- 방어책
  1. **Checks-Effects-Interactions**: 검사 → 상태 변경 → **외부 호출은 맨 마지막**
  2. **뮤텍스 락**: 실행 중 재진입을 잠그는 상태 변수 (OpenZeppelin `nonReentrant`)

**접근 제어**: 컨트랙트 함수는 기본적으로 누구나 호출 가능 → 민감 함수(발행, 수수료 변경, 인출)에 제어가 없으면 무한 발행·자금 유출. 방어: 명확한 modifier, 검증된 라이브러리, **멀티시그·타임락**

**OpenZeppelin**: 오래 검증된 표준 라이브러리
- 토큰(ERC20, ERC721=NFT) / 접근제어(역할: ADMIN_ROLE, MINTER_ROLE) / 보안 유틸(`nonReentrant`, `pause()/unpause()`, SafeCast, ECDSA 서명 검증, 머클 트리 검증) / 업그레이드 패턴 / **Contracts Wizard**(웹 UI로 코드 생성)

> [!warning] 헷갈리기 쉬운 포인트
> - `assert`: 강의 기준 "실패 시 모든 가스 소비". 실제 0.8 이후 컴파일러는 Panic으로 처리하며 남은 가스를 환불하지만, **시험은 강의 내용 기준**으로 답할 것
> - `view` vs `pure`, `private` vs `internal`, `external`은 **내부 호출 불가**
> - `storage→storage`, `memory→memory`는 **참조**, 나머지는 복사
> - modifier는 inline 복사 → 배포 가스↑ / calldata는 복사 생략 → 가스↓
> - 매핑: **전체 delete 불가, 키 단위만 가능**, storage 전용, 키로 mapping/struct/동적 배열 불가
> - 노트 오타 주의: `boold` → `bool`, `adress` → `address`, 구조체 예제의 `User` / `Voter` 혼용

31. 캐시백: 수신자 B의 캐시백 비율이 5%, A가 B에게 1,000ht를 보낸다면 B가 받는 금액과 A에게 돌아오는(A가 덜 내는) 금액은? (수업 예제 기준: 캐시백만큼 제외하고 송금)

> [!question]- 정답
> 26. 확률 독립 가정. **A && B**: A(50) 항상 평가, A가 true일 때(50%)만 B(150) 평가 → 50 + 0.5×150 = **125**. **B && A**: B(150) 항상 평가, B가 true일 때만 A(50) → 150 + 0.5×50 = **175**. 가벼운 조건을 앞에 두면 평균 비용이 낮다(강의 예시: 125 → 100과 같은 원리).
> 27. totalSupply = 10000 × 10² = **1,000,000**, 배포자 balanceOf도 **1,000,000**
> 28. **재진입 취약**: 외부 `call` 이후에 잔액을 0으로 바꿈. 수정: `balances[msg.sender] = 0;`을 **call 이전**으로 옮김(Checks-Effects-Interactions) 또는 `nonReentrant` 락 적용
> 29. ① 지역 변수로 `mapping`을 `memory`로 선언할 수 없음(mapping은 **storage 전용**, 지역 변수는 storage 참조 형태만 가능) ② `delete m;` — **매핑 전체 삭제 불가**(키 단위 `delete m[addr]`만 가능)
> 30. ① 성공 ② 성공(onlyOwner=A) ③ **실패**(받는 주소 블랙리스트) ④ **실패**(보내는 주소 블랙리스트) ⑤ **실패**(B는 owner가 아님) ⑥ 성공 ⑦ 성공. 최종: A = 10,000 − 2,000 − 2,000 = **6,000**, B = **4,000**
> 31. 비율 5% → 캐시백 = 1,000 × 5% = **50ht**, B가 실제 받는 금액 = **950ht**, A에게 돌아오는 금액 = **50ht** (송금액에서 캐시백 금액을 제외하고 송금하는 구현). 비율 0이면 전액, 100이면 0
