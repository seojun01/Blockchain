## Part 1. 반드시 알아야 할 핵심 내용

### 1~2주차 — 블록체인 탄생과 기초
- **블록체인 = 분산원장(Distributed Ledger)**: 트랜잭션을 블록에 묶어 체인으로 연결, 모두가 같은 장부를 공유 → 위·변조 방지, 투명성
- **탈중앙(decentralized)**: 중앙 관리자 없이 공동 검증 / **분산(distributed)**: 데이터가 네트워크 전반에 복제
- **화폐 역사 흐름**: 금본위제(금화본위 → 금핵본위) → **브레튼우즈 체제(1944~1971, 달러 기축통화)** → **닉슨 쇼크(1971, 금태환 정지)** → 신용화폐 → **서브프라임 모기지 사태(2008)** → 비트코인 백서(2008)
  - 금본위제 장점: 신뢰성, 인플레이션 방지 / 단점: 자산 이상 발행 불가 → 경제 확장의 족쇄
  - 신용화폐 한계: 중앙집중 구조, 인플레이션 위험(하이퍼인플레이션)
- **사이퍼펑크(Cypherpunk)**: 암호(cipher)로 프라이버시 보호 + 감시에 저항(punk)
- **디지털 화폐 종류**: 전자화폐(실물화폐를 디지털로, 카카오페이) / 가상화폐(플랫폼 내 사용, 게임머니) / **암호화폐**(분산원장 + 암호기술, 중앙기관 없음)
- **전신들**: David Chaum **eCash**(1983 은닉 서명 → 1989 DigiCash → 1998 파산, 중앙기관이 이중지불 검증) / Wei Dai **B-Money**(1998, 분산원장·PoW·PoS 개념, 구현 안 됨)
- **비트코인**: 사토시 나카모토, 2008 백서, 2009 프로토타입, 제네시스 블록 메시지 *"The Times 03/Jan/2009 Chancellor on brink of second bailout for banks"*
- **비트코인 철학**: 금본위제 회귀(희소성) + 탈중앙·분산 장부 + 암호기술로 신뢰
- **기본 용어**: 노드(풀·라이트·검증자·채굴 노드), 지갑(자산 관리 SW/HW, MetaMask), 계정, 주소, 트랜잭션(상태 변화 기록), 블록(헤더 + 바디), 블록 해시(블록 지문)
- **이중 지불(Double spending)**: 같은 화폐를 두 번 사용 → 장부 불일치 때문에 발생 → **합의**로 대표 장부 선정·동기화해 해결
- **블록체인 거래 흐름**: 트랜잭션 생성 → 브로드캐스트 → 각 노드 검증(서명·잔액·중복) 후 블록 생성 → 블록 전파 → 합의로 대표 블록 선정 → 체인에 기록
- **비트코인의 금본위제 관점**: 총 발행량 **2,100만 개**, 채굴(특정 값 찾는 연산), 발행량 예측 가능
- **분류**
  - 기능 관점: **허가형(Permissioned)** — 사전 승인된 노드만 검증 (보안·성능·규제 친화, 탈중앙성 제한) / **비허가형(Permissionless)** — 누구나 참여 (탈중앙, 낮은 성능·높은 합의 비용)
  - 운영 관점: **Public**(비트코인, 이더리움 — 투명, 느림) / **Private**(단일 조직, 높은 TPS — Hyperledger Fabric, R3 Corda) / **Hybrid**(공개+비공개 병행) / **Consortium**(여러 기관 공동 운영)
- **응용**: DeFi(스마트계약 기반 금융, EOA·CA), DID(탈중앙 신원 — 자기주권 신원, 선택적 공개), 제품 추적, 전자투표, DAO, 토큰화, 저작권

### 3주차 — 블록체인을 위한 암호기술
- **해시 함수**: 임의 길이 입력 → 고정 길이 출력, 비밀 정보 없는 공개 함수

| 성질 | 의미 | 지문 비유 |
|---|---|---|
| 역상 저항성 | y가 주어질 때 h(x)=y인 x 찾기 어려움 | 지문만 보고 누구인지 알 수 없음 |
| 제2역상 저항성 | x가 주어질 때 h(x)=h(x′)인 다른 x′ 찾기 어려움 | Alice와 같은 지문을 가진 사람 찾기 |
| 충돌 저항성 | h(x)=h(x′)인 서로 다른 쌍 아무거나 찾기 어려움 | 지문이 같은 두 사람 찾기 |

- **눈사태 효과**: 입력 1비트 차이 → 출력 완전히 바뀜
- **해시 종류**: MD5(취약, 비권장) / SHA-1(160비트, 충돌 공격 가능) / SHA-2(224·256·384·512) / **SHA-3 = Keccak**(2012 선정, **스펀지 구조**) / BLAKE(빠름, BLAKE2 = RFC 7693) / **Poseidon**(대수적 연산, 영지식 증명 친화)
- **머클 트리**: 트랜잭션 해시를 단계적으로 합쳐 **머클 루트** 하나로 요약 → 루트만 비교해도 전체 무결성 확인
  - **머클 증명**: 루트 + 머클 경로만 있으면 포함 여부 증명, 경로 크기 **O(log N)** (100만 개 ≈ 해시 20번)
- **전자서명**: 개인키로 서명, 공개키로 검증 (공개키 암호의 역변환). 긴 메시지는 **해시 값에 서명** s = Sig_sk(h(m))
  - 제공 성질: **무결성, 메시지 출원 인증, 부인 방지**
  - RSA(σ = mᵈ mod n, 서명 크고 느려서 블록체인에 부적합) / **ECDSA**(secp256k1, 비트코인·이더리움, RSA 3072 ≈ EC 256 ≈ 128비트 보안) / **EdDSA**(Ed25519, 결정적·부채널 공격에 강함, 솔라나·카르다노)
- **고급 서명**: **집계 서명**(여러 서명 → 하나, BLS, 이더리움 2.0) / **다중 서명**(t-of-N, 지갑·DAO)
- **영지식 증명(ZKP)**: 비밀을 공개하지 않고 참임을 증명 (동굴 예시)
  - 성질: **완전성**(참이면 항상 수락), **건전성**(거짓이면 수락시킬 수 없음), **영지식성**(참이라는 사실 외 정보 없음)
  - 기법: Fiat-Shamir, zk-SNARKs, zk-STARKs / 활용: DID(나이 증명), **ZK 롤업**

### 3주차 — 합의 알고리즘
- **합의 핵심 요소**: **안전성**(모순된 이력 확정 X), **생존성**(멈추지 않고 진행), **최종성**(확정 블록은 되돌아가지 않음), **장애 허용**
- **위협**: 패킷 지연·손실, 비잔틴 장군(이중 지불, 검열, 스팸, **Sybil 공격** — 가짜 노드 대량 생성)
- **체인 분기(Chain Fork)**: 대표 블록이 동시에 2개 이상 생성 → 분기 선택 규칙으로 수렴
  - 비트코인: **최장 체인 규칙(Longest Chain, 누적 작업량)** → 확률적 최종성, 버려진 블록 = **스테일 블록**, 동률이면 작은 해시값 등 기준
  - 이더리움: **(LMD-)GHOST** / BFT 계열: **2/3 이상 투표**
- **하드포크 vs 소프트포크**

| | 하드포크 | 소프트포크 |
|---|---|---|
| 호환성 | 옛 노드와 **비호환** | **하위 호환** (규칙이 엄격해짐) |
| 결과 | 두 체인으로 분리될 수 있음 | 하나의 체인 유지 |
| 예 | BTC ↔ BCH, ETH ↔ ETC | **SegWit**(2017) |

- **합의 알고리즘 비교**

| | PoW | PoS | DPoS | PBFT |
|---|---|---|---|---|
| 참여 자격 | 해시 연산 자원 | 예치 지분 | 투표로 선출된 대표자 | 허가된 참여자 |
| 장점 | 단순, 오랜 운영 | 에너지↓, 명시적 최종성 | 매우 높은 확장성 | **즉시(결정적) 최종성** |
| 단점 | 자원 소모, **51% 공격** | 부의 집중, 설계 복잡 | 대표자 집중(탈중앙↓) | 참여자↑ → 통신량 폭증 |
| 벌칙 | — | **슬래싱** | 투표로 교체 | — |

- **PoW 해시 퍼즐**: H(Data ‖ Nonce) < 목표값이 될 때까지 넌스 증가 (찾기 어렵고 검증 쉬움). 전용장비 **ASIC**
- **PBFT**: f개 악의적 노드 허용 → 최소 **3f + 1**개 노드, 동일 메시지 **2f + 1**개로 합의
  - 단계: **Request → Pre-Prepare → Prepare → Commit → Reply**

### 4주차 — 비트코인
- **주소 생성**: 개인키 →(타원곡선 상수곱)→ 공개키 →(**SHA-256 → RIPEMD-160**)→ **Base58** 인코딩 (메인넷 버전 0x00). 반대 방향은 불가능(비가역)
  - Base58: 헷갈리는 0, O, I, l 제거
- **노드 기능 모듈**: Wallet / Full Blockchain / Network Routing / Miner
- **노드 종류**: Reference Client(Bitcoin Core, 모든 기능) / **풀 노드**(전체 블록 저장·검증) / **SPV(라이트) 노드**(블록 헤더만) / Solo Miner
- Peer 발견: 캐시(TCP **8333**) → DNS Seed → 하드코딩 Seed IP
- **블록 헤더(80바이트)**: 버전(4) / 이전 블록해시(32, 이중 SHA-256) / 머클루트(32) / 타임스탬프(4) / 난이도 Bits(4) / 넌스(4)
  - 트랜잭션 홀수 개면 마지막을 복사해 짝수로
  - 타임스탬프: 이전 11개 블록 중간값보다 커야, 네트워크 시간보다 2시간 이상 미래면 안 됨
- **블록 바디**: 트랜잭션 카운터 + **코인베이스 트랜잭션(첫 번째)** + 트랜잭션 리스트
- **UTXO 모델**: 잔액 = 사용 가능한 UTXO의 합. 송금 시 기존 UTXO를 **통째로 소비**하고 새 UTXO(수신자 + 거스름돈) 생성
- **트랜잭션 구조**: 입력(소비할 UTXO + 소유권 증명 = 해제 스크립트 **ScriptSig**) / 출력(금액 + 잠금 스크립트 **ScriptPubKey**)
  - **P2PKH**(공개키 해시, 표준) / P2SH(복합 조건, 다중서명) / P2WPKH·P2WSH(SegWit)
- **수수료 = 입력 합 − 출력 합** (채굴자는 수수료 높은 것 우선)
- **코인베이스 트랜잭션**: 이전 UTXO 참조 X, ScriptSig에 임의 데이터, 출력 = 블록 보조금 + 수수료 합
- **SegWit**: 2017 소프트포크, 서명 데이터 분리 → 확장성 (기존 1MB 제한 → 최대 4M weight)
- **난이도**: **2016블록마다** 재계산, 평균 **10분**에 1블록. nBits → 목표값 **T = C × 2^(8(E−3))** (E = 상위 1바이트, C = 하위 3바이트)
- **반감기**: **210,000블록(약 4년)**마다 보조금 절반, 총 2,100만 개
- **네트워크 동작**: 트랜잭션 생성·전파 → 검증(서명, UTXO 중복, 스크립트) → **MemPool** → 후보 블록 + 넌스 찾기 → 블록 전파 → 블록 검증(이전 해시, 트랜잭션, 머클루트, PoW) → 최장 체인 → 보상, MemPool에서 삭제
- 거래 확정은 보통 **6 컨펌**

### 5~6주차 — 이더리움
- **비트코인 한계**: 보안(RBF + Zero Confirmation 이중지불, **51% 공격**) / 기능(스크립트가 단순·**튜링 불완전**, 반복·재귀 없음)
- **이더리움**: 비탈릭 부테린, **백서 2013**, 개빈 우드 **황서 2014**(기술 사양), 메인넷 2015.07.30
- **계정 모델**(UTXO 아님): **EOA**(개인키로 통제, 코드 없음) / **CA**(코드 보유, 스스로 트랜잭션 생성 불가 — **모든 트랜잭션의 출발점은 EOA**)
- **계정 필드**: nonce(보낸 트랜잭션 수 / CA는 생성한 계약 수), balance(Wei, 1 ETH = 10¹⁸ Wei), codeHash(바이트코드의 keccak256, 변경 불가), storageRoot(저장소 MPT 루트)
- **주소**: EOA = 공개키 Keccak-256 해시의 **마지막 20바이트** (EIP-55 대소문자 체크섬) / CA = 배포자 주소 + nonce 해시
- **스마트 컨트랙트**: 조건 충족 시 자동 실행 (자판기 비유), 배포 후 코드 불변, **결정적** 실행
- **EVM**: Solidity → Op code → **EVM 바이트코드**, 모든 노드가 같은 입력에 같은 출력
- **가스(Gas)**: 무한 루프(튜링 정지 문제) 방지
  - 수수료 = **사용 가스량 × 가스 가격**, gwei = 10⁻⁹ ETH
  - 남은 가스는 환불 / 가스 소진 시 상태 변경 **취소(reverted)** + 사용 가스 **환불 X**
- **노드**: 풀 노드(프루닝) / 라이트 노드(헤더) / 아카이브 노드(모든 과거 상태, 12~14TB)
- **The Merge(2022.09.15, PoS 전환)** 이후: **실행 계층(EL**, EVM) + **합의 계층(CL**, 검증·최종성) 분리
- **블록 정보**: Slot(12초), Epoch(32슬롯 ≈ 6.4분), Gas Used/Limit, **Base Fee(소각)**, Parent Hash, StateRoot, WithdrawalsRoot, Nonce(PoS 이후 0)
  - 총 수수료 = Gas Used × (Base Fee + Priority Fee)
- **트랜잭션**: Type-0(Legacy: nonce, gasLimit, gasPrice, to(CA 생성 시 null), value, V/R/S, data) / **Type-2(EIP-1559)**: Base Fee(자동 조정·소각) + Priority Fee(팁) 분리, Max Fee 상한
- **이더리움 PoS**: **32 ETH** 예치 → 검증자 후보, 매 슬롯 제안자 무작위 선정, 에포크마다 투표, 분기 선택 **LMD-GHOST**, 최종성 **Casper FFG(지분 2/3)**
- **블록체인 트릴레마**: 탈중앙성 · 확장성 · 보안성 동시 달성 어려움
