
### 비트코인의 한계 파악
- #### 이더리움의 탄생
	- 화폐가 아닌 다른 서비스를 제공하기 위해 블록체인을 활용하려는 시도
	- Vitalik Buterin
		- 이더리움 아이디어 제공자, 공동 창립자
		- 이더리움을 제안하는 백서 발행
- #### 비트코인의 한계 - 보안 측면
	- ##### RBF & Zero Confirmation 공격
		- 2021년 \#666,833 블록 근처에서 RBF 거래에 따른 $21가 이중 지불 되었음이 보도됨
		- 오보임이 밝혀졌지만 공격 가능성으로 인해 시장 불안감 조성
		- RBF(Replace-By-Fee)기능
			- 트랜잭션이 공식 블록 시퀀스에 저장되지 않았지만 승인된 것으로 간주함
			- 신속한 거래를 위해 리스크를 안고 진행
			- 일반적으로 트랜잭션은 검증을 받은 다음 MemPool에 저장된 후 블록 시퀀스에 연결될 때까지 시간이 필요하며, 거래 확정을 위해 6번 컴펌을 기다림
	- RBF & Zero Confirmation 공격을 통한 이중지불
		- 공격자는 상점에서 비트코인으로 상품을 주문
		- 상점은 zero confirmation 기능을 통해 트랜잭션을 임의로 확정하고 즉시 상품을 인도
		- 주문자는 상점에서 나오자마자 RBF 기능을 이용하여 트랜잭션을 회수
		- 이어서 수수료를 두 배 올리고 수신자 정보를 변경하여 새로운 트랜잭션 생성 후 재배포
		- 새로운 트랜잭션이 선택 받고 승인 됨
	- ##### PoW 51% 공격
		- 블록체인 노드의 사용자 또는 그룹(마이닝 풀)이 전체 채굴 능력 대부분을 절반 이상을 제어하는 경우 발생
		- (2014) 인기 마이닝 풀 Ghash.io가 전체 해시레이트가 거의 50%에 육박함
		- (2025) 두 대형 마이닝 풀 Foundry USA와 AntPool이 한 때 합산 해시파워가 50%를 넘김
		- PoW 51% 공격을 통한 이중지불
			- [[6.이더리움 기초_2026.pdf#7]]
- #### 비트코인의 한계 - 기능 측면
	- 비트코인은 화폐 거래(송금) 기능에만 초점이 맞춰져 있음
		- 이중 지불 방지, 희소성 있는 디지털 자산, 탈중앙화 동작 등을 목적으로 설계
	- 비트코인 스크립트
		- 단순성 중시
			- 모든 노드가 효율적으로 동일하게 검증하여 합의에 대한 안전성 및 생존성 제공
		- 튜링 불완전성
			- 간단한 프로세스만 처리 가능
			- 반복, 재귀가 없고 극도로 제한된 메모리 사용
### 이더리움의 대표 특징 이해 & 비트코인과 차이점 비교
- #### 이더리움 탄생 배경
	- 블록체인 위에서 화폐 기능 분만 아니라 범용 프로그램이 동작한다면?
- #### 이더리움 백서와 황서
	- 백서
		- 2013년 발행 by 비탈릭 부테린
		- 이더리움의 비전, 목표, 핵심 요소에 대한 개념 소개
	- 황서
		- 2014년 공개 by 개빈 우드 (공동 창립자)
		- 이더리움 네트워크 구현을 위한 공식 기술 사양 문서
- #### 계정 모델
	- 상태를 계정 단위로 관리하고 트랜잭션을 통해 특정 계정의 상태를 갱신
	- 외부 소유 계정(EOA)과 계약 계정(CA) 두 가지 유형이 존재
- #### 스마트 컨트랙트
	- 이더리움 네트워크 위에서 자동으로 실행되는 프로그램
		- 계약 계정에 코드와 영구 상태(storage)를 포함
		- 트랜잭션, 메시지 호출에 결정적으로 반응
	- 중개자 없이 당사자 간 상호 신뢰 없이도 거래나 계약 이행이 가능하도록 구현
	- 자동화에 의한 작동 원리
		- 입력 조건이 충족되면 자동으로 실행되고 미충족되면 실행되지 않음
		- 자판기에 비유
			- 동전을 넣고 버튼을 누르면 커피가 제공된다는 **계약**을 구현
	- 스마트 컨트랙트 실행
		- \[작성 및 배포]
			1. 컨트랙트 코드 작성
			2. 배포 트랜잭션 생성 및 전송
			3. 블록에 포함된 후 계약 계정 생성
			4. 해당 주소에 컨트랙트 코드 저장 (이후 불변)
		- \[실행]
			1. 계약 주소로 호출할 함수, 인자 등을 담아 트랜잭션 전송
			2. 네트워크의 검증 노드는 해당 트랜잭션으로 컨트랙트 코드를 실행하고 검증함
			3. 컨트랙트 실행에 의해 코드를 따라 상태를 변경하거나 결과가 반환됨
- #### 이더리움 가상 머신 (EVM)
	- 이더리움 네트워크 노드의 기기에서 실행되는 바이트코트 실행 소프트웨어
		- 독립된 이더리움 가상 기계 환경을 통해 스마트 컨트랙트를 실행
		- 상호 운용성 제공 : 모든 노드가 동일한 입력에 대해 동일한 출력을 얻음
			- 이질적 구성의 네트워크에서 항상 동일한 실행 환경을 보장
				- 블록체인에 접속한 기기는 어떤 하드웨어와 OS를 사용하고 있을지 알 수 없음
	- EVM에서의 컨트랙트 코드 실행
		- 컨트랙트(코드)는 실제로 모든 노드에서 실행되는 EVM 바이트코드를 나타냄
		- Solidity로 작성된 컨트랙트가 Op code를 거쳐 EVM Bytecode로 컴파일되는 구조
- #### 이더리움 특징
	- ##### 가스 경제
		- 스마트 컨트랙트에 **무한루프**가 있을 경우
			- 튜링 머신은 무한 루프가 발생하는지 사전에 결정하지 못함 (튜링 정지 문제)
			- 무한 루프에 빠지면 관련 노드가 계산에 묶여 리소스 고갈 및 서비스 지연 유발
				- P2P 네트워크 특성상 모든 노드를 일괄적으로 종료하고 재시작하여 복구하기 어려움
				- 비트코인이 간단한 스크립트만 지원하는 이유
		- EVM에서 연산을 수행할 때 필요한 가스 소모량을 사전에 정의
			- 트랜잭션 처리 과정에서 수행하는 계산에 가스 수수료가 발생
			- 가스 수수료를 통해 ETH 단위의 실제 비용이 결정
				- 가스 수수료 = 사용 가스량 * 가스 가격
		- 가스 기반 수수료
			- 가스 한도 : 해당 트랜잭션이 사용할 수 있는 최대 연산량 -> 무한 루프를 방지
			- 가스 가격 : 네트워크 혼잡도에 따라 gwei(10^-9 ETH)단위로 지정
			- 예시 1![[스크린샷 2026-10-14 at 20.15.36.png]]
				- 사용하지 않은 가스는 돌려받음
			- 예시 2![[스크린샷 2026-10-14 at 20.16.28.png]]
				- 무한 루프에 빠지게 되면 가스를 모두 소진하고 프로세스 종료
				- 상태 변경이 취소되고 실패한 트랜잭션으로 기록됨
				- 사용된 가스는 환불되지 않음
		- 수수료 팁으로 지정된 수수료의 일부는 검증자가 수취
			- 지불하고자 하는 수수료가 높을수록 검증자가 얻는 가치가 상승
			- 높은 가스 비용을 지불하게 되면 블록에서 선택할 가능성이 높아짐
			- (비트코인 거래 수수료와 동일한 개념)
